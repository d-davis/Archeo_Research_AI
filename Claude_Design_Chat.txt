How would this system read a shapefile. Does it need all the components or just the .shp file?


ThinkingSonnet 4.6
It needs more than just the .shp file. A shapefile is actually a bundle of files that must all live in the same folder together. The minimum required set is:



.shp: the geometry (shapes themselves)
.dbf: the attribute table (all the columns your data has)
.shx: the shape index (links geometry to attributes)


Without .dbf, GeoPandas can load the geometry but gets zero attributes, so the system's archaeological column heuristics and attribute statistics would have nothing to work with. Without .shx, it often fails to open at all.



There's one more you really want:



.prj: the CRS/projection definition. Without this, gdf.crs returns None and the system flags "No CRS defined" in the notes, which degrades the spatial extent and coordinate interpretation.


So practically: always keep .shp, .dbf, .shx, and .prj together in the same folder. When you pass --files features.shp to the CLI, GeoPandas automatically looks for the sibling files by the same base name in the same directory. You only reference the .shp in the command, but the others must be present alongside it.



If you only have the .shp file (e.g. someone sent just that), the system won't crash but the output will be nearly useless, just geometry counts with no attributes or projection info.
